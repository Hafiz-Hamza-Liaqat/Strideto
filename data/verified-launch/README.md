# Verified data launch packs

This directory is the **only** location a real verified-data launch manifest may
live. Nothing here is loaded automatically: there is no startup seeding, no
boot hook, no migration hook. Applying a launch batch is an explicit operational
action.

## What belongs here

A launch manifest may contain a record **only** when the record is real and
already carries accepted first-party provenance. Concretely, every record must
declare `provenance.origin` as one of:

- `real_source_backed` — Strideto-verified against a first-party source
- `institution_official` — Mission 18 institution-submitted official data,
  which keeps its `institution_official` attribution and never silently becomes
  Strideto-independent verification

Records declaring `synthetic_fixture`, `demo_placeholder`,
`insufficiently_sourced` or `legacy_unknown` are rejected by the validator. A
synthetic or demo record can never be promoted into verified launch data by
attaching a URL to it.

## What does NOT belong here

- Test fixtures — those live in `server/src/__tests__/fixtures/verifiedLaunch/`
  and the loader refuses to read any path containing a test/fixture segment.
- Demo or placeholder content — see `server/src/data/betaContent/`.
- Anything generated by an LLM. Mission 19 Copilot may not author launch facts.

## Running a dry run

```bash
node scripts/verified-data-launch.mjs --manifest initial-launch-pack.v1.json
```

Dry run is the default and the only mode Mission 25 executes. It performs zero
persistence, opens no database connection and makes no network request.
